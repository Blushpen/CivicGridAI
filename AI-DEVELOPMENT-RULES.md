# AI Development Rules

1. Read the project PDF and this repository context before making changes.
2. Never invent requirements that are not in the project brief.
3. Keep the product scope focused on the hackathon demo and the documented MVP vertical slice.
4. Prefer the smallest safe implementation that preserves artifact quality and demo reliability.
5. Reuse existing types, services, and components before creating new abstractions.
6. Do not modify unrelated modules.
7. Run the safest available build/typecheck/test command after meaningful changes.
8. Keep all AI-assisted code understandable enough for a judge Q&A.
9. Never commit secrets, tokens, API keys, or environment data.
10. Preserve a clear separation between deterministic business logic and AI-driven classification.
11. If a decision changes, update `DECISIONS.md` and `PROJECT-CONTEXT.md`.
